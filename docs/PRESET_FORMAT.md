# Preset format

User presets are UTF-8 JSON files with the extension `.afpreset` in
`~/Library/Application Support/ZackAMP/Presets/`. Factory presets use the same schema and are
embedded in the app (`Resources/FactoryPresets/NN-name.json`, generated by
`Scripts/make_factory_presets.py`; the numeric prefix is the curated list order).

## Schema (version 4)

```json
{
  "format": "ampforge.preset",
  "schemaVersion": 4,
  "name": "Brit Crunch",
  "category": "Classic Rock",
  "description": "Vintage British crunch: chords ring, single notes bite.",
  "author": "Z.AMP Factory",
  "parameters": {
    "amp.model": 3,
    "amp.gain": 0.66,
    "eq.b750": -4.0,
    "out.level": -2.0
  },
  "cabinet": {
    "a": { "irId": "factory:br-4x12-v25-cap", "irName": "UK 4x12 Vintage 25W — Cap" },
    "b": { "irId": "", "irName": "" }
  }
}
```

* `format` must be `ampforge.preset`.
* `parameters` maps **stable parameter IDs** to **plain values** in the units below (not normalised).
  Saved presets contain every parameter; hand-written ones may omit any.
* `cabinet.*.irId` references the IR library (`factory:…` or `user:<uuid>`); `irName` is only used to
  name a missing IR in warnings. IR audio is never embedded.
* `category` is one of: Clean, Edge of Breakup, Blues, Classic Rock, British Crunch, Lead, High Gain,
  Modern Metal, Ambient, User.

These IDs are also the future plugin automation IDs: **never rename or reuse an ID**; add new ones.
Choice indices are append-only (new amp models get new indices).

## Loading rules (robustness)

* Not JSON / wrong `format` / `schemaVersion` < 1 → rejected with a message; nothing changes.
* Unknown parameter IDs → ignored with a warning (forward compatibility).
* Non-numeric values → ignored with a warning; out-of-range values are clamped; choices/toggles are
  rounded; NaN/Inf → default.
* Missing parameters → defaults, except `amp.preampValve` / `amp.powerValve`, which default to the
  preset's amp model's usual valves (so presets saved before the valve selectors sound unchanged).
* `schemaVersion` greater than the app's → loaded best-effort with a "made by a newer version" warning.
* Missing IR → amp model's default cabinet + warning naming the missing IR.
* Corrupt files in the user folder are skipped and reported in the status bar; files > 1 MB are ignored.

## Versioning and migration

`PresetCodec::kSchemaVersion` is the current version. When the schema changes:
1. bump `kSchemaVersion`;
2. add a migration step in `PresetCodec::fromJson` (marked `migrations`) that transforms a version-N
   document into version N+1 (e.g. renaming an ID, rescaling a value);
3. add a test with a stored old-version preset.

### Migrations

* **1 → 2** (new amp line-up): `amp.model` is mapped Lacquer Clean → JC120, Lacquer Tweed → Tweed,
  Plexi → JCM800, Albion Lead → JCM800, Cascade Lead → Coliseum, Cascade Heavy → Triple, and the
  valve selectors are reset to the new model's usual valves.
* **2 → 3** (selector reordered clean → high gain): `amp.model` is renumbered from the order the
  models were added (Tweed, JC120, AC30, JCM800, Coliseum, MP1, Triple, Dual, Plexi, 5150) to selector
  order, so every preset opens on the same amp. Version-1 presets map straight to version 3; their
  old "Plexi" now opens on the Plexi (it used to map to the JCM800).
* **3 → 4** (reverb Mix became dry/wet with level-matched tails; CS-3 gives less make-up):
  `reverb.mix` is multiplied by 10^(-trim/20) for the preset's reverb type (trim = how much louder
  that type's tail now is), and `comp.level` gains back the CS-3 make-up that was removed, so the
  preset sounds the same.

## Writing

* Writes go to a temporary sibling file followed by an atomic rename; a crash or full disk cannot leave
  a half-written preset.
* Names are unique (case-insensitive) among user presets and must not equal a factory preset name.
  *Save As* refuses collisions; *Save* overwrites only the currently loaded user preset.
* If two names map to the same legal filename, a numbered filename is used — nothing is overwritten.
* Deleting moves the file to the Trash where the OS supports it.

## Session state

On quit, the exact current sound (including unsaved edits) is stored in the settings file as a
preset document and restored on the next launch, together with which preset it came from.
